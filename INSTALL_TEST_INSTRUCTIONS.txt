5. Run journal-side indexed validation
--------------------------------------

From repository root:

  python journal/run_region_index_validation.py

Generated files:

  journal/region_index_validation.json
  journal/region_index_validation_summary.csv
  journal/region_index_candidate_pairs.csv

The script exits with status 1 if any indexed result differs from the current
linear/all-pairs reference implementation.


6. What the journal-side script validates
-----------------------------------------

For 1D, 2D, 3D, and 4D presence domains:

A. Prefix-query equivalence
   - RegionPrefixIndex.subsuming_cells()
     vs brute-force subsumes(r, query)
   - RegionPrefixIndex.subsumed_cells()
     vs brute-force subsumes(query, r)
   - RegionPrefixIndex.compatible_candidates()
     vs brute-force compatible(r, query)
   - RegionPrefixIndex.contains()
     vs current region_algebra.contains()

B. Intersection equivalence
   - intersection_indexed(A, B)
     vs current region_algebra.intersection(A, B)

C. Incremental index integrity
   - repeated add/discard operations
   - query results checked after updates

D. Candidate-pair counts
   - naive pair count: |A| * |B|
   - indexed compatible candidate-pair count

The candidate-pair CSV is structural evidence only. It must not yet be described
as a wall-clock speedup result.

8. Optional later API exposure
------------------------------

After validation, bst_id/__init__.py may optionally expose:

  from .region_index import RegionPrefixIndex, intersection_indexed

This is not required for functionality and is intentionally omitted in the
first validation step.


9. Current scope
----------------

This bundle indexes:
  - contains / ancestor-subsumption queries
  - descendant queries
  - compatibility candidate retrieval
  - Intersection candidate enumeration

It does NOT yet replace normalize() with a trie-indexed normalizer.
Therefore the final normalization step of intersection_indexed() still uses
the current reference normalize() implementation.
